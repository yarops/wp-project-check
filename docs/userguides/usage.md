# Запуск и параметры

## Что проверяется

Техническая корректность кода WordPress-проекта и соблюдение формальных требований: языка, платформы, API и технических соглашений, зафиксированных в репозитории. Бизнес-логика, полнота фич и соответствие продуктовой задаче в охват не входят. Описание задачи или критерии приёмки для запуска не нужны.

Скилл только читает код и запускает диагностические команды. Исходники, конфигурацию и данные сайта он не меняет и дефекты не исправляет. В проекте появляются только отчёт и его HTML-копия.

## Параметры

| Параметр | Значения | По умолчанию |
|---|---|---|
| `scope` | `diff` (нужен `base`), `feature` (нужен `subject`), `global` | `global` |
| `areas` | `tooling`, `reliability`, `security` | все три |
| `target` | `plugin`, `theme`, `site` | определяется по кодовой базе |

### `scope`

- `diff` — изменения относительно `base` (ветка, тег или коммит), считая от merge-base, и их влияние на существующее поведение. Незакоммиченные изменения включаются в проверку и отмечаются в отчёте.
- `feature` — код одной функции или сценария вместе с путём выполнения: хуками, маршрутами, классами в других файлах.
- `global` — весь собственный код. Перечень файлов берётся полностью, а файлы, не прочитанные ни в одной области, перечисляются в ограничениях.

Ядро WordPress, сторонние плагины, `vendor/` и `node_modules/` — зависимости. Их код не ревьюится, но читается, когда от их поведения зависит вывод.

### `areas`

| Область | Что делает |
|---|---|
| `tooling` | Запускает команды проекта (линтеры, статанализ, `php -l`, проверку типов, аудит зависимостей, изолированные тесты) и разбирает вывод. Отмечает обязательные проверки, которых нет в CI. |
| `security` | Строит реестр точек входа и проверяет права, nonce, владение объектами, санитизацию и экранирование, пути вывода защищаемых данных. |
| `reliability` | Проверяет обработку `WP_Error` и `false`/`null`, некорректный ввод, порядок загрузки, ресурсы, механизмы с состоянием на стыках PHP, JS, cookie и хранилищ, завершение повторов. |

`architecture` и `operations` пока не реализованы. Если их запросить, скилл сообщит об этом и не подменит другой проверкой.

### `target`

Определяется по признакам: PHP-файл с `Plugin Name:` — плагин; `style.css` с `Theme Name:` — тема; `wp-config.php`, структура Bedrock или `wp-content` с собственным кодом — сайт. Указывать нужно, только если признаки неоднозначны, например в монорепозитории.

## Как задать параметры

Строкой, YAML или обычным языком — запрос переводится в те же параметры.

```text
/wp-project-review scope: diff, base: main, areas: reliability, security
```

```yaml
scope:
  type: feature
  subject: импорт CSV
areas: [reliability, security]
```

```text
Проверь весь плагин перед релизом
Посмотри права в REST-маршрутах
Прогони линтеры и статанализ
```

Явно указанные `scope` и `areas` ограничивают проверку. Уточняющие вопросы задаются только по существенным пробелам: нет `base` для `diff`, `subject` не находится в коде, неясно, что проверять.

## Какие команды запускаются

Только в области `tooling` и только диагностические. Не запускаются:

- автоисправление (`phpcbf`, `--fix`);
- миграции, импорт данных, сборка, перезаписывающая отслеживаемые файлы;
- установка и обновление зависимостей — только с вашего разрешения;
- тесты и скрипты, которые обращаются к живой БД, внешним сервисам или работающему сайту;
- WP-CLI против любого сайта.

Если по команде и конфигурации нельзя установить, что она безопасна, команда не запускается, а проверка получает статус «не проверена» с причиной. Из внешних обращений допустимы только чтение результатов CI и аудит зависимостей. Кэши инструментов допустимы.

Вне `tooling` запускается одна команда — сборка HTML-копии отчёта скриптом скилла.

Находка, которую нельзя подтвердить без запуска сайта или запроса к endpoint, остаётся гипотезой.

В Claude Code запуск команд подчиняется вашим настройкам разрешений. Для длинного прогона без подтверждений подходит режим `auto`.

## Время и стоимость

Ориентир — `scope: global` всех трёх областей на теме из ~130 файлов собственного кода, модель Claude Opus:

| Показатель | Значение |
|---|---|
| Длительность | 11–14 минут |
| Пик контекста | 280–330 тыс. токенов |
| Стоимость по прайсу | $5–6 |

Расход растёт с объёмом прочитанного кода. `diff` и `feature` заметно дешевле, а запуск одной области дешевле всех трёх.

## Результат

- Отчёт: `docs/reviews/wp-project-review-YYYY-MM-DD-HHMMSS.md` относительно корня проекта. Другой путь можно указать в запросе. Существующие файлы не перезаписываются.
- HTML-копия рядом, с тем же именем.
- В ответе агента — пути к файлам, краткий итог и главные ограничения покрытия.
