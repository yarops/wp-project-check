# Как читать отчёт

Пример целиком — [docs/examples/demo-arcade/report.md](../examples/demo-arcade/report.md) и его [HTML-копия](../examples/demo-arcade/report.html).

## Разделы

1. **Параметры проверки** — объект и признаки, по которым он определён; границы собственного кода; охват (для `diff` — проверяемое состояние); запрошенные и выполненные области; основания, найденные в репозитории (стандарты кода, требования к версиям, соглашения).
2. **Итог** — число находок по важности и типу, проверки, которые не выполнены или выполнены частично, главные ограничения. Новых выводов здесь нет.
3. **Находки** — сначала подтверждённые дефекты, затем гипотезы, затем недостаток технического контекста; внутри групп — по убыванию важности.
4. **Покрытие** — по каждой области статусы проверок и места, вошедшие в проход:
   - `tooling` — сводка запусков с фактическим охватом каждого инструмента;
   - `security` — «проверено N из M», реестр точек входа, статусы сквозных проверок;
   - `reliability` — механизмы с состоянием с участниками и рассмотренными состояниями.
5. **Ограничения и открытые вопросы** — что не проверено и почему; вопросы, ответ на которые изменит вывод.
6. **Рекомендации** — улучшения без установленного дефекта, без уровня важности.

Вердикта «готово к релизу» нет. Решение о релизе принимается по правилам проекта, отчёт даёт для него находки и покрытие.

## Находка

```markdown
#### SEC-1. <суть одной фразой>

- **Область / тип / важность:** security · подтверждённый дефект · High
- **Место:** файл и строка, функция, точка входа (E-3)
- **Основание:** правило платформы, контракт API или соглашение репозитория
- **Доказательство:** путь выполнения, правило и место, разобранное сообщение инструмента
- **Условия:** нужные права, конфигурация, действия пользователя
- **Последствия и обоснование важности:** …
- **Направление исправления:** без готового патча
```

У гипотезы есть ещё поля **Чего не хватает** и **Как подтвердить**.

Если вывод зависит от поведения ядра WordPress или плагина, в доказательстве указаны файл и строка их локального исходника.

## Тип замечания

- **Подтверждённый дефект** — есть доказательство нужного вида: достижимый путь, нарушенное правило с местом, конфликт значений.
- **Гипотеза** — доказательства не хватает; указано, чего именно и как подтвердить. Важность предварительная.
- **Недостаток технического контекста** — нет основания для вывода, например неизвестна задуманная модель доступа. Не дефект.
- **Рекомендация** — улучшение без установленного дефекта.

## Важность

Шкала едина для всех областей и назначается конкретной находке, а не пункту чеклиста.

| Уровень | Критерий |
|---|---|
| Critical | Компрометация системы, массовая утечка, необратимая потеря критичных данных |
| High | Существенное нарушение доступа, целостности данных или работоспособности функции |
| Medium | Ограниченный ущерб или нарушение части функциональности при приемлемом обходном пути |
| Low | Незначительный дефект без существенного влияния на доступ, данные и работоспособность |

Нужные права и конфигурация учитываются, но не понижают уровень автоматически. Если требуемые права и так легитимно дают тот же результат (например, `unfiltered_html`), находка снимается. P0/P1/P2 не используются: приоритет исправления — решение проекта.

## Статус проверки

В покрытии у каждой проверки один из статусов: пройдена; обнаружено нарушение; неприменима (с причиной); не проверена (с причиной); выполнена частично (с границами).

## ID

| ID | Что это |
|---|---|
| `SEC-N`, `REL-N`, `TOOL-N` | находки этого отчёта |
| `E-N` | точки входа в реестре `security` |
| `REC-N` | рекомендации |
| `SEC-CHK-N`, `REL-CHK-N`, `TOOL-CHK-N` | проверки методики; постоянны между отчётами, поэтому по ним удобно сравнивать прогоны |

## HTML-копия

Рядом с отчётом лежит `.html` с тем же именем. Это один файл без внешних зависимостей, он открывается локально в браузере:

- сводка по важности и областям;
- находки карточками с фильтрами по важности, типу и области;
- ID в тексте — ссылки на находки, точки входа и рекомендации;
- покрытие свёрнуто, оглавление сбоку, светлая и тёмная тема, печать.

Источник — Markdown. Если вы поправили `.md` или HTML не собрался (например, нет `python3`), соберите его вручную:

```bash
python3 ~/.claude/skills/wp-project-review/scripts/report-html.py docs/reviews/<отчёт>.md
```

Путь к скрипту зависит от того, куда установлен скилл.
