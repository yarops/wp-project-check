## Оценка на других проектах

Сейчас методика проверена на одном регрессионном кейсе (см. [пример](../../examples/demo-arcade/)). Следующий шаг — прогоны на проектах других типов: плагин с платежами или REST API, сайт на Bedrock, блочная тема, headless. Для каждого нужна своя таблица ожидаемых дефектов, собранная независимой сверкой. Без этого нельзя отличить общий метод от подгонки под один проект.

## Области `architecture` и `operations`

- `architecture` — соблюдение принятых в проекте границ модулей, слоёв и зависимостей с конкретными последствиями нарушений.
- `operations` — миграции, конфигурация окружения, восстановление и откат для конкретного окружения.

Каждая область появится вместе со своим reference и контрактом проверок. До этого запрос этих областей отклоняется.
