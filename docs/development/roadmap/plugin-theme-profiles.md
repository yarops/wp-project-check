# Профили плагинов и тем

Статус: бэклог.

## Идея

Сохранить один вход `wp-project-review` и вынести специфичные проверки в профили. Общий процесс остаётся в общей части: контекст, инструменты, требования к доказательствам, классификация, отчёт, завершение. Профиль выбирает и дополняет общие проверки с учётом объекта. Выбор профиля не делает проверку обязательной: применимость определяется возможностями проекта.

| Профиль | Кандидаты в специфичные проверки |
|---|---|
| Плагин | Активация, обновление, деактивация, удаление; миграции; capabilities; публичные API; фоновые задачи; совместимость с темами |
| Тема | Иерархия шаблонов; вывод контента; возможности редактора; подключение ресурсов; совместимость с плагинами |
| Блочная тема | Дополнительно `theme.json`, шаблоны и части шаблонов, стили, паттерны |
| Дочерняя тема | Зависимость от родительской темы, переопределения, поведение при обновлении родителя |

Блочная и дочерняя темы — особенности профиля темы, которые могут сочетаться.

Требования каталогов публикации (WP.org) — отдельные профили поставки. Их нужно сверять с актуальными официальными источниками.

## Возможная структура

```text
references/
├── common/        # нынешние project-context, tooling, reliability, security, reporting
└── profiles/
    ├── plugin.md
    ├── theme.md
    ├── wporg-plugin.md
    └── wporg-theme.md
```

Структура предварительная; переносить общие файлы до реализации профилей не нужно.

## Смешанные проекты

Для проекта со своей темой и плагином применяются оба профиля в согласованном охвате. Отдельно учитывается их взаимодействие: распределение ответственности, зависимости, совместимость. Находки не дублируются.

## Условия реализации

- Общая часть опробована на проектах разных типов.
- Для специфичных проверок определены применимость, основание, доказательства и условие прохождения по общему [контракту](../contract.md).
- Проверки темы не наследуют неприменимые требования плагина, и наоборот.
- Проверены сценарии отдельного плагина, отдельной темы и смешанного проекта.

Отдельные `wp-plugin-review` и `wp-theme-review` имеет смысл рассматривать, только если практика покажет существенные различия в сценариях, инструментах и процессе. До тех пор — один скилл с профилями, без дублирования общих инструкций.
