SEC-1

Код плеера декодирует HTML-сущности после kses и выводится как HTML — stored XSS от пользователей без unfiltered_html

Highдефектsecurity
  • Место: app/Components/Player.php:107 (Player::buildIframe()), вывод — resources/views/components/player/iframe.php:11 и src/scripts/player.ts:137 (innerHTML); точки входа E-10, E-11.
  • Основание: правило платформы — значения, сохранённые пользователем без unfiltered_html, проходят kses и не должны превращаться в исполняемую разметку (SEC-CHK-2).
  • Доказательство:
    1. Поле player_iframe (textarea плагина полей) доступно на экране редактирования записи, то есть ролям contributor и author для своих записей.
    2. Плагин полей при сохранении для пользователя без unfiltered_html вызывает wp_kses_post_deep() (secure-custom-fields/includes/acf-form-functions.php:136). Kses удаляет теги, но сохраняет именованные сущности (wp_kses_normalize_entities(), wp-includes/kses.php:2184): строка &lt;img src=x onerror=alert(1)&gt; остаётся как есть.
    3. Player::buildIframe() вызывает html_entity_decode() (Player.php:107), и строка становится разметкой <img src=x onerror=alert(1)>.
    4. iframe.php:11 выводит её без экранирования; в ветке с заставкой player.ts:137 вставляет её через innerHTML по клику.
  • Условия: учётная запись с правом редактировать записи без unfiltered_html (contributor, author).
  • Последствия и обоснование важности: выполнение произвольного JS в контексте сайта, в том числе в сессии администратора, открывшего предпросмотр. Требуемые права такого результата сами по себе не дают. High.
  • Направление исправления: не декодировать сущности после сохранения; допускать в поле только iframe с белым списком атрибутов и хостов; на клиенте не вставлять данные через innerHTML.
SEC-2

Публичный REST-маршрут рейтинга определяет голосующего по подделываемым заголовкам

Mediumдефектsecurity
  • Место: app/Api/Controllers/RatingsController.php:44 (маршрут POST demo-arcade/v1/ratings/(?P<post_id>\d+), permission_callback возвращает true); app/Modules/Ratings.php:146 (getUserIdentifier()), :170 (getClientIp()). E-1.
  • Основание: техническая гарантия, установленная кодом: setRating() хранит оценку по ключу пользователя и при повторной оценке заменяет её — механизм объявляет «одна оценка на пользователя».
  • Доказательство: для гостя ключ — ip_<адрес>; getClientIp() берёт адрес сначала из HTTP_CLIENT_IP, HTTP_X_FORWARDED_FOR и ещё четырёх заголовков и лишь затем из REMOTE_ADDR. FILTER_VALIDATE_IP проверяет только формат. Доверенного прокси в коде нет. Каждый запрос с новым значением Client-IP создаёт новый ключ и увеличивает счётчик.
  • Условия: нет; маршрут доступен без входа.
  • Последствия и обоснование важности: неограниченная накрутка рейтинга, неограниченный рост меты _user_ratings. Medium: искажение данных одной функции без доступа к остальным.
  • Направление исправления: использовать REMOTE_ADDR, а заголовки — только от доверенного прокси из конфигурации; ограничить частоту голосов.
SEC-3

Плеер и описание записи, защищённой паролем, выводятся без проверки пароля

Mediumдефектsecurity
  • Место: resources/views/content/single.php:38, :80; resources/views/content/home.php:52; app/Components/Player.php:49.
  • Основание: неявная защита платформы — пароль записи проверяется внутри get_the_content() (wp-includes/post-template.php:319); прямое чтение меты эту проверку минует (SEC-CHK-2).
  • Доказательство: шаблон записи выводит основной контент через the_content(), но плеер и мету short_description — через get_post_meta() без post_password_required(). Главная выводит те же поля в карточке записи.
  • Условия: запись с паролем; посетитель без пароля.
  • Последствия и обоснование важности: защищённое паролем содержимое (игра и описание) доступно всем. Medium.
  • Направление исправления: проверять post_password_required() перед выводом плеера и мет в обоих шаблонах.
REL-1

Сервер не выводит маркер data-favorites-page в пустой ветке — восстановление избранного не запускается

Mediumдефектreliability
  • Место: resources/views/content/favorites.php:53–73; src/scripts/components/favorites.ts:77–88.
  • Основание: техническая гарантия, установленная кодом: favorites.ts восстанавливает cookie из localStorage и перезагружает страницу, только найдя маркер, выведенный сервером.
  • Доказательство: маркер выводится внутри ветки «есть избранное». Когда cookie истёк (30 дней) или очищен, сервер рендерит пустую ветку без маркера, и восстановление не запускается — именно в том состоянии, для которого оно написано.
  • Условия: cookie избранного истёк или удалён, данные остались в localStorage.
  • Последствия и обоснование важности: пользователь видит пустую страницу избранного при сохранённых данных. Medium.
  • Направление исправления: выводить маркер страницы в обеих ветках.
REL-2

Исключение доступа к localStorage обрывает инициализацию всех модулей страницы

Mediumдефектreliability
  • Место: src/scripts/components/favorites.ts:12; src/scripts/app.ts:21–30.
  • Основание: контракт browser API — обращение к localStorage бросает SecurityError, когда хранилище для сайта запрещено.
  • Доказательство: initFavorites() читает localStorage вне try и вызывается первым в app.ts; исключение прерывает вызовы initMenu(), initCarousel(), initPlayer(), initRating().
  • Условия: браузер запрещает сайту хранить данные.
  • Последствия и обоснование важности: на всех страницах не работают меню, карусель, игра и рейтинг. Medium.
  • Направление исправления: обернуть доступ к хранилищу в try и изолировать инициализацию модулей друг от друга.
REL-3

Синхронизация избранного перезагружает страницу бесконечно, если браузер отверг cookie

Mediumдефектreliability
  • Место: src/scripts/components/favorites.ts:29–34, :77–88.
  • Основание: условие завершения повтора (REL-CHK-12); присваивание document.cookie результата не возвращает, а cookie сверх лимита размера браузер молча отвергает.
  • Доказательство: при расхождении cookie и localStorage код записывает cookie и вызывает location.reload(). Если запись отвергнута, после перезагрузки расхождение то же, и цикл повторяется без ограничения.
  • Условия: список избранного, сериализация которого превышает лимит cookie.
  • Последствия и обоснование важности: страница избранного недоступна. Medium.
  • Направление исправления: проверять, что cookie записан, перед перезагрузкой; ограничить число попыток маркером в sessionStorage.
REL-4

Сохранение записи перезаписывает счётчик рейтинга значением формы

Lowдефектreliability
  • Место: app/Admin/Metaboxes/Rating.php:24, :55–65, :124–142; app/Modules/Ratings.php:32, :49–56.
  • Основание: техническая гарантия, установленная кодом: setRating() полагается на согласованность _rating_sum, _rating_count и _user_ratings.
  • Доказательство: поле счётчика называется _rating_count, и плагин полей пишет значение формы прямо в эту мету на acf/save_post с приоритетом 10 (acf-form-functions.php:217). Обработчик темы на приоритете 20 срабатывает при любом сохранении записи и пересчитывает сумму из среднего, округлённого до 2 знаков. Голоса, поданные пока редактор был открыт, выпадают из агрегатов.
  • Условия: редактирование записи, на которую в это время голосуют; либо count от ~100 (сдвиг округлением).
  • Последствия и обоснование важности: небольшое искажение статистики рейтинга. Low.
  • Направление исправления: пересчитывать агрегаты только при фактическом изменении поля.

5. Ограничения и открытые вопросы

  • Реальный риск SEC-1 зависит от того, есть ли на сайте пользователи с ролями contributor и author.
  • Согласованность pnpm-lock.yaml с package.json не проверена: нужна установка зависимостей, она не запускалась без разрешения.

6. Рекомендации

  • REC-1. Добавить CI с phpcs, phpstan и tsc, которые проект уже требует запускать вручную.
  • REC-2. Заявить минимальные версии PHP и WordPress и настроить PHPCompatibility.
  • REC-3. Убрать из веб-доступного каталога исходников тесты и демо-скрипты либо закрыть каталог правилами веб-сервера.
