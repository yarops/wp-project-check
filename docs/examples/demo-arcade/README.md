# Пример: тема demo-arcade

Обезличенный пример на основе реального регрессионного кейса, на котором сравниваются версии скилла. Названия, пространства имён, маршруты и пути изменены; устройство кода и найденные дефекты сохранены.

- [report.md](report.md) — сокращённый отчёт в формате скилла.
- [report.html](report.html) — его HTML-копия, собранная `scripts/report-html.py`. Скачайте файл и откройте локально.

## Проект

Классическая тема WordPress для каталога браузерных игр: около 130 файлов собственного кода.

- PHP: `app/` (PSR-4, контейнер, провайдеры, компоненты), шаблоны в `resources/views/`.
- Фронтенд на TypeScript: плеер игры, рейтинг, избранное, меню, карусель.
- Поля записей — на плагине Secure Custom Fields (API ACF).
- Публичный REST-маршрут голосования, избранное в cookie с резервной копией в `localStorage`, CLI-скрипты импорта и экспорта демо-данных.
- PHPCS, PHPStan, Stylelint и TypeScript настроены, CI нет.

Чем проект удобен для проверки: большинство дефектов в нём не видны из одного файла. Они возникают на стыке PHP-шаблона и TypeScript, cookie и `localStorage`, плагина полей и обработчика темы, а также там, где платформа применяет защиту неявно и код её обходит.

## Результаты прогонов

`scope: global`, все три области, модель Claude Opus. Находка засчитывается по причине и пути, а не по формулировке.

| Версия методики | Найдено из 12 | Ложные срабатывания | Стоимость | Пик контекста |
|---|---|---|---|---|
| исходная, прогон 1 | 7 | 0 | — | — |
| исходная, прогон 2 | 7 | 0 | — | — |
| проверки механизмов с состоянием | 10 | 0 | — | — |
| сквозные проверки security, reliability для CLI | 8 | 0 | $5.64 | 326k |
| контракт возврата на запись | 7 | 0 | $4.98 | 284k |

Расход в ранних прогонах не измерялся.

Что из этого следует:

- **Устойчиво** — дефекты 1, 2 и 6, все пять прогонов.
- **Дефекты на стыках компонентов** (3, 7, 8) стали находиться после появления проверок механизмов с состоянием и путей вывода защищаемых данных, но не в каждом прогоне.
- **Разброс между прогонами** одной версии сопоставим с эффектом отдельной правки методики: одного прогона мало, чтобы судить о правке.
- **10 из 12** — на версии, где пример в методике почти дословно описывал дефект 7. Пример затем заменён нейтральным. На этом кейсе такой результат показывает, что агент следует методу, но не что метод обобщается.
- **Часть пропусков** вызвана не методикой, а исполнением: в одном прогоне листинг каталога был усечён, и три CLI-скрипта не попали в чтение. После этого для `global` требуется полный перечень файлов.

Прогонов на других проектах пока нет. Без них нельзя утверждать, что результат переносится.
